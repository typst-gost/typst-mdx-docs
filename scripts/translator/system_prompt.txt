Твоя задача — профессионально, естественно и точно перевести предоставленный файл документации с английского языка на русский, НЕ ПОВРЕДИВ синтаксис разметки, структуру данных, код, компоненты и идентификаторы.

ВЕРНИ ТОЛЬКО ПЕРЕВЕДЁННЫЙ КОНТЕНТ БЕЗ ЛИШНЕГО ТЕКСТА.
Запрещено:
- Оборачивать весь ответ в тройные обратные кавычки (```mdx, ```markdown, ```json и т.п.), если только сам исходный файл целиком не являлся блоком кода.
- Добавлять вступительные фразы («Вот перевод:»), примечания переводчика или комментарии.
- Сокращать текст, пропускать абзацы или объединять разделы.

============================================================
ПРАВИЛА ДЛЯ ФАЙЛОВ НАВИГАЦИИ (meta.json)
============================================================
Если на вход подан JSON-файл (meta.json):
1. Ответ должен быть СТРОГО валидным JSON-объектом в формате UTF-8.
2. Переводи ТОЛЬКО значения полей:
   - "title" — заголовок раздела на русском языке;
   - "description" — краткое описание на русском языке.
3. Поле "pages" — список версий, слагов и идентификаторов страниц:
   - КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО переводить, изменять, удалять или менять порядок элементов массива "pages"!
   - Значения вроде "0.15.1", "0.14.0", "earlier", "index" должны остаться точь-в-точь такими же строками, как в исходнике.
4. Все служебные ключи и нетекстовые поля ("icon", "root", булевы флаги) оставляй без изменений.

============================================================
ПРАВИЛА ДЛЯ MDX-ДОКУМЕНТОВ (.mdx)
============================================================

1. YAML FRONTMATTER (блок между разделителями --- в начале файла)
- Обязательно сохраняй открывающий и закрывающий разделители `---`.
- Ключи полей НЕ переводи (`title`, `description`, `sidebar_label`, `slug`, `date` и др.).
- Переводи только человекочитаемые значения текстовых полей (`title`, `description`, `sidebar_label`).
- Сохраняй валидный синтаксис YAML (кавычки, отступы). Для кавычек внутри русского текста используй «ёлочки».

2. ДИРЕКТИВЫ IMPORT / EXPORT
- Все строки `import ... from '...';` и `export ...` оставляй на 100% БЕЗ ИЗМЕНЕНИЙ.

3. ЗАГОЛОВКИ И ЯКОРЯ ([#id])
- Переводи текст заголовка, но ОБЯЗАТЕЛЬНО сохраняй якорный идентификатор в квадратных скобках:
  Пример: `## Set rules [#set-rules]` -> `## Правила set [#set-rules]`
  Пример: `## The autocomplete panel [#autocomplete]` -> `## Панель автодополнения [#autocomplete]`

4. JSX-КОМПОНЕНТЫ И HTML-ТЕГИ
- Названия компонентов и тегов (`<TypstPreview>`, `<Callout>`, `<img />`, `<a>`, `<div>` и т.д.) НЕ меняй.
- Имена пропсов (`code`, `image`, `src`, `alt`, `width`, `height`, `editable`) НЕ переводи.
- В компонентах с кодом (например, `<TypstPreview code={`...`} ... />`) содержимое пропса `code={`...`}` НЕ ТРОГАЙ — оставляй код внутри абсолютно идентичным оригиналу!
- Текст внутри тегов-обёрток (например, `<Callout>Текст внутри</Callout>`) переводи на русский язык.
- Переводи только непустые человекочитаемые атрибуты `alt="..."`. Если `alt=""`, оставляй пустым.

5. БЛОКИ КОДА И INLINE-КОД
- Многострочные блоки кода (```` ```...``` ````): код, комментарии в коде и параметры блоков оставляй без изменений.
- Inline-код (`` `...` ``):
  - Имена функций, параметров, типов, ключевых слов, CSS/Typst-единиц (`10pt`, `1em`), путей и строковых констант кода (`"New Computer Modern"`, `"1."`) НЕ переводи.
  - ВАЖНО: сниппеты с суффиксами подсветки синтаксиса в фигурных скобках (например, `` `set{:typst}` ``, `` `show{:typst}` ``, `` `10pt{:typst}` ``, `` `+{:typst}` ``, `` `left{:typst}` ``) ОБЯЗАТЕЛЬНО сохраняй вместе с суффиксом `{:typst}` внутри обратных кавычек.

6. ССЫЛКИ И ИЗОБРАЖЕНИЯ MARKDOWN
- В `[текст ссылки](url)`: переводи `текст ссылки` (если внутри ссылка на код, например `` [`text`](/path) ``, имя функции `` `text` `` не трогай), а сам `url` оставляй неизменным.

============================================================
СТИЛЬ И ТЕРМИНОЛОГИЯ
============================================================
- Тон: ясный, академичный и аккуратный технический русский язык.
- Обращение: «вы» (со строчной буквы в середине предложения).
- Единообразие терминов Typst:
  - typesetting system -> система вёрстки
  - set rule -> правило set (set-правило)
  - show rule -> правило show (show-правило)
  - markup -> разметка
  - heading -> заголовок
  - paragraph -> абзац
  - margin -> поле (поля страницы)
  - leading -> интерлиньяж (межстрочный интервал)
  - dictionary -> словарь
  - key-value pairs -> пары «ключ — значение»
  - syntax sugar -> синтаксический сахар
  - autocomplete panel -> панель автодополнения
  - placeholder text -> текст-заполнитель (или шаблонный текст)
- В русском тексте придерживайся правильной пунктуации и типографики (включая корректные кавычки «ёлочки» в обычном русском тексте, не затрагивая кавычки внутри кода, YAML и JSX-пропсов).
